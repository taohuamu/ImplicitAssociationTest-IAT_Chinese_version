# IAT 中文版 · 配置驱动实现

内隐联想测验（Implicit Association Test）的中文可运行版本，基于 PsychoPy。
实验内容（概念词、属性词、指导语）全部写在 `config.yaml` 里，换实验材料不需要改代码。

原仓库的 `IAT.py` / `IAT.psyexp` / 三个 xlsx 文件**保持原样未改动**，作为存档保留。

---

## 一、跟原版的区别

| 项 | 原版 | 本版 |
|---|---|---|
| 运行环境 | Python 2，现代 PsychoPy 打不开 | Python 3.10–3.12，PsychoPy 2021 之后的版本 |
| 改实验材料 | 改 3 个 xlsx，左右位置靠约定 | 改 `config.yaml`，程序启动时校验 |
| 中文显示 | 字体写死 Arial，中文变方框 | 自动选系统中文字体 |
| 试次平衡 | 每个类别必须正好 5 个例子 | 任意数量，自动平衡 |
| 配对顺序 | 靠被试编号奇偶反推 | 编号前缀 T/F 显式指定，且写入数据 |
| 计分 | 需要装 R + RStudio | `score.py`，纯 Python |
| 数据列 | `accuracy` 是反向的（1 = 错） | 拆成 `first_key_correct`（1 = 首答正确）等自解释列 |

## 三、跑起来

### 1. 自检（改完配置必做）

```
python run.py --check-only
```

不弹窗口，只打印区块结构和刺激分配，用来确认配置没写错。
配置有问题会直接告诉你哪一行错了，例如：

```
配置有 1 处问题，已停止：
  1) 两个概念词必须在不同侧（现在都在 right 侧）
```

也可以指定顺序：`python run.py --check-only --id F001`

### 2. 正式施测

```
python run.py --id T001
```

不写 `--id` 会弹出输入框；如果图形库不可用，会自动退回命令行输入，不会卡死。

**编号规则**：`T` 或 `F` 开头 + 数字。

- `T001`、`T2`、T012…… → **正顺序**：花在右（与积极同侧），先做相容配对
- `F001`、`F12`、F003…… → **反顺序**：花在左，先做不相容配对

这是配对顺序的平衡机制。奇偶不重要，前缀决定一切。编号会被写进数据，计分时不用再猜。

### 3. 计分

```
python score.py
```

默认读 `iat/data/` 下所有 csv，输出 `iat/data/processed.csv`。

## 四、改配置

只改 `config.yaml`。三个地方最常用：

> 不用装编辑器：双击同目录下的 **`edit.cmd`**，会用记事本打开 `config.yaml`。
> 千万不要用 Word 或 WPS 打开——它们会改掉文件格式，程序就读不了了。
> 改完保存，再双击 `check.cmd` 确认没写错。

**换概念词**

```yaml
concepts:
  - name: 花
    side: right
    exemplars: [玫瑰, 百合, 兰花, 荷花, 菊花]
```

`side` 表示"正顺序（T）时它在哪一侧"。反顺序会自动左右互换。

**换属性词**

```yaml
attributes:
  - name: 积极
    side: right
    exemplars: [喜爱, 和平, 愉快, 快乐, 拥抱]
```

属性词的左右位置**全程固定**，不参与互换。

**换指导语**

`instructions` 下面每一段对应一个屏幕。`{L}` `{R}` 会自动替换成当前左右两侧的类别名，
`{KEY_L}` `{KEY_R}` 替换成实际按键，**这几个占位符要保留**。

**七个说明页是模板化的**：正文部分统一写在 `instruction_common` 里，
每页只写开头那一句（比如"第三部分：前面出现过的四类词语，现在同时出现"）再加一个
`{COMMON}` 引用共用正文。**改共用正文只需改一处，七页同时生效**，
不会出现七页措辞不一致。

还有一个 `{ERROR_RULE}`，**由程序按该区块的实际设置自动填**：

| 该区块的 `error_handling` | `{ERROR_RULE}` 实际显示 |
|---|---|
| `correct` | 按错了，屏幕下方会出现红叉，按对的键才能继续。 |
| `advance` | 按错了不用改，直接进入下一个词。 |

所以指导语里**不要自己写"按错会怎样"**——写死的话，一旦改了 `error_handling`，
说明页就会和被试实际遇到的情况对不上。留一个 `{ERROR_RULE}` 让程序填即可。

同意页（`consent`）与致谢页（`thanks`）**按空格键**继续；七个说明页**按 E 或 I 键**继续，
与作答键一致，被试不用在空格和字母键之间切换。

`consent` 是知情同意页，里面有 `【请填写】` 的地方要换成你所在机构和伦理批号。
现在正文 17 行，占屏高约 50%；加到 28 行以上字号就会偏小，届时建议拆成两页。

### 配置的硬性规则

程序启动时会检查，不满足就停下：

1. 概念、属性各正好 2 个
2. 两个概念分居两侧；两个属性分居两侧
3. 每个概念的 `side` 必须与某个属性相同（否则不存在相容配对）
4. `keys.left` 与 `keys.right` 不能相同，且都是单字符
5. 同一类别的 `exemplars` 不能重复、不能为空
6. 四个名字（两个概念 + 两个属性）必须两两不同，且不能和刺激词重名
7. `timing.stim_delay` 与 `rt_timeout` 必须是非负数
8. 指导语里只能用 `{L}` `{R}` `{KEY_L}` `{KEY_R}` `{ERROR_RULE}` `{COMMON}` 六个占位符；
   正文要显示花括号得写成 `{{ }}`，否则启动时就报错
9. `error_handling` 的键只能是 `default` 或当前布局里存在的区块号，
   值只能是 `correct` 或 `advance`

## 六、数据格式

每次施测生成两个文件：

- `data/T001_20261027_153012.csv` — 逐试次数据，UTF-8 BOM 编码，Excel 可直接打开
- `data/T001_20261027_153012.json` — 本次实验的完整配置快照，便于复现

CSV 每行一个试次，列的含义：

| 列 | 含义 |
|---|---|
| `participant` | 被试编号 |
| `order` | T / F，配对顺序 |
| `block` | 区块序号 1–7 |
| `block_kind` | `concept` / `attribute` / `combined` |
| `pairing` | `compatible` / `incompatible`，单类别区块为空 |
| `error_mode` | `correct`（红 X + 强制改正）/ `advance`（答错直接过） |
| `trial_in_block` | 区块内第几个试次 |
| `trial_type` | `concept_1` / `concept_2` / `attribute_1` / `attribute_2` |
| `stimulus` | 实际呈现的词语 |
| `stim_side` | 该词应该归到哪一侧 |
| `correct_key` | 正确按键 |
| `first_key` | 被试第一次按的键 |
| `first_key_correct` | 1 = 首答正确，0 = 首答错误 |
| `rt_first` | 首次按键的反应时（秒） |
| `rt_correct` | 改正后正确反应的反应时（秒），计分用这个 |
| `n_errors` | 该试次按错的次数 |

## 七、计分说明

`score.py` 输出的 `processed.csv` 一行一个被试，关键列：

- `D1` — **主指标**。正值表示相容条件（花-积极）反应更快，即对花有更积极的内隐态度
- `D1a` / `D1b` — 短块对、长块对的 D 值，D1 是两者的平均
- `D_1998_log` — Greenwald(1998) 对数法，只作参考，**数值与 D1 不可比**
- `exclude` / `exclude_reason` — 是否建议剔除及原因

**计分算法**：严格按 Greenwald, Nosek & Banaji (2003) 的 Table 4，共 12 步：

1. 只用区块 3、4、6、7（含两个练习区块）
2. 剔除 RT > 10000 ms 的试次；剔除「>10% 试次快于 300 ms」的被试
3. 区块内全部试次参与，不丢前两个
4. 默认不做极端值处理
5. 逐区块算**正确试次**的均值与标准差
6. 区块 3&6 一个合并 SD、4&7 一个合并 SD，**只用正确试次算**
7. 错误试次：强制改正的用改对后的时间；不改正的替换为「区块正确均值 + 600 ms」
8. 不做对数等变换
9–12. 各区块取均值 → 两个差值（6−3、7−4）→ 各除以第 6 步的 SD → 两个商取平均

参数在 `config.yaml` 的 `scoring` 段：

| 参数 | 默认 | 说明 |
|---|---|---|
| `rt_max` | 10000 | 剔除慢于此值的试次（毫秒） |
| `fast_rt` | 300 | 快速试次阈值 |
| `fast_pct_limit` | 0.10 | 快速试次比例上限，超过就剔除被试 |
| `error_rate_exclude` | `null` | 错误率剔除线。**2003 原文没有这条**，默认关闭；填 `0.20` 才启用 20% 标准 |
| `delete_below_400` | `false` | 设 `true` 即原文的 D2/D6 变体（删除 <400ms 试次） |
| `error_penalty` | 600 | advance 模式错误试次的时间惩罚 |

> **第 6 步是关键**：SD 必须只用正确试次算。若把带改正耗时的错误试次也算进去，
> SD 会偏大、D 被系统性低估。用 T10 实测：正确做法 D1 = 0.247，算错只有 0.203。

**答错处理与计分的关系**（`error_handling`）：

| 模式 | 施测行为 | 记的反应时 | 计分处理 |
|---|---|---|---|
| `correct` | 显示红 X，必须按对键才能继续 | 按到正确键的时间（含改正耗时） | 直接用 |
| `advance` | 不显示任何反馈，答错直接下一试次 | 那一次错按的时间（偏快） | 换成该区块正确试次均值 **+600ms** |

`advance` 的 600ms 惩罚是 Greenwald et al. (2003) D 算法的标准做法。
不加的话，错误试次那些"很快的错按"会把均值拉低，人为夸大或缩小 D 值。

两套模式混用时，计分是按每个试次自己记录的
`error_mode` 分别处理的，不会互相污染。

## 八、时间精度

反应时是这个实验的核心指标，这里说明它是怎么测的。

**刺激出现时刻**：用 `win.flip()` 的返回值，即显卡 `glFinish()` 记录的真实翻转时刻。
不用配置里的 `stim_delay`（标称值）——实测标称 0.3 秒时，刺激真正出现在 0.306~0.325 秒之间，
如果拿标称值当基准，每一条反应时都会被系统性地多算 6~25 毫秒。

**按键时刻**：用 PsychoPy 事件队列里的事件时间戳（`event.getKeys(timeStamped=clock)`），
不是发现按键那一刻的轮询时刻。

**刺激出现之前的按键会被丢弃**，不会被当成提前反应。

**残留误差**：约一个刷新周期。因为 pyglet 是在事件分发时才给按键打时间戳的，
所以反应时被量化到帧边界。120 Hz 屏幕下约 8 毫秒，60 Hz 下约 17 毫秒。
这是 PsychoPy + pyglet 架构的固有下限，不是本程序的 bug。

**怎么验证的**：用独立参照（`flip` 返回后在 trial clock 上立刻取时刻）构造了 200 个
精确在刺激后 200 ms 的按键事件，跑完整程序后落盘的 `rt_correct` 与真值的
平均误差 0.15 ms、最大 0.80 ms；另外插入一个刺激前 50 ms 的按键，验证它被正确丢弃。

**想进一步降低误差**：
- 用全屏模式（本程序默认全屏）
- 显示器刷新率设到 120 Hz 以上并确认显卡驱动没开垂直同步干扰
- 关掉其他占用 GPU 的程序
- 如果要做 EEG/眼动，可以把 `timing` 改成按帧计时，但需要针对具体硬件标定

## 九、常见问题

**中文显示成方框**
字体没找到。在 `config.yaml` 里把 `font: auto` 改成具体字体名，例如 `font: SimHei`。

**按 E/I 没反应**
中文输入法会吞掉按键。施测前务必关闭输入法（切到英文状态不够，要彻底退出）。

**中途按了 Esc**
数据会写到当前试次，但后续区块缺失，该被试需重做。

**换了词表，旧数据还能一起分析吗**
不能。不同词表的 D 值不可比，请分开存放、分开分析。

**想改成 Greenwald(1998) 五部分布局**
把 `experiment.layout` 改成 `greenwald5`，试次变成 140，其余不变。

**启动时报 `the environment variable is longer than 32767 characters`**
这是 PsychoPy 初始化时往环境变量里塞第三方包路径导致的，Windows 单变量上限 32767 字符。
本项目的 `run.cmd` 里已经设了 `PSYCHOPYNOPACKAGES=1` 规避。
如果用别的方式启动，自己加这个环境变量，或者在 Python 里 `os.environ['PSYCHOPYNOPACKAGES']='1'` 后再 import psychopy。

**命令行输出中文是乱码或报 `UnicodeEncodeError`**
中文 Windows 控制台默认 GBK，`run.cmd` 里已经 `chcp 65001` 切到 UTF-8。
如果直接 `python run.py` 看到乱码，多半是终端编码问题，不影响数据；程序本身已做保护，
不会再因输出字符编码而崩溃。
